# 开发路线与验收

优先级已由用户确认：两种用法都要，先打通手机新任务链路。阶段编号是研发顺序，不承诺日期；0.1.0 是骨架版本，后续版本由实际范围决定。

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 0：基础 | 调研、独立仓库、扩展骨架、CI、构建与审计、维护方案 | 本地检查与 GitHub 三平台 CI 通过，配置可复核 |
| 1：QQ 新任务 | QQ 私聊 → 原生 Codex → 状态/结果；一个授权项目 | 真机收发、Codex 实际执行、身份拒绝、重复指令、取消、重启恢复通过 |
| 2：VS Code 管理 | 项目别名、授权、任务列表、桌面与手机状态 | 隔离宿主真实操作；窄面板、中英文、断连状态；扩展关闭后的行为可解释 |
| 3：已有会话 | 列表、空闲会话续聊/分支、明确交接、提问与审批 | 区分原线程与 fork；活跃线程互斥；准确匹配审批；Windows 单独验收 |
| 4：微信 | 腾讯微信插件接入 | 版本兼容、私聊、扫码、授权撤销与重连实测，修复问题有证据 |
| 5：扩展场景 | 手机网页、多机器、SSH/容器、语音或附件 | 每项有独立连接、权限、隐私和真机验收记录 |

## 下一轮可直接开始的工作

- [ ] 按 `openclaw-poc.md` 锁定并验证 QQ + OpenClaw + 原生 Codex 组合。
- [ ] 确认可复用的现有项目/会话接口；决定 AnyDevice 控制层扩展点。
- [ ] 定义新任务指令和脱敏事件格式，写明项目、会话与审批权限。
- [ ] 完成单项目私聊执行与回传，测试重复消息、断连和取消。
- [ ] 实现 VS Code 项目登记和任务状态；完成隔离宿主检查。

运行中既有 VS Code 会话接管不提前承诺；若当前客户端无法共享控制连接，界面提供等待空闲或明确分支，而非模拟点击审批按钮。
